# Как добавить игру в MVP

Движок читает не Markdown напрямую, а собранный JSON. Исходники книги лежат в
`games/<id-игры>/`, сборка превращает их в `public/games/<id>.json`.

```text
games/steel-rat/
  game.yaml      манифест: название, старт, метаданные сцен
  story.md       сцены: ## ключ, текст, выборы
  items.yaml     предметы (если есть)
  assets/        иллюстрации и звук (если есть)
        ↓  npm run games:build
public/games/steel-rat.json + public/games/steel-rat/assets/…
```

## 1. Куда положить книгу

Создай папку `games/<id>/`, где `<id>` — латиница, цифры, дефис (`steel-rat`,
`koshchei-cave`). Внутри — минимум два файла:

| Файл | Обязателен | Что внутри |
|---|---|---|
| `game.yaml` | да | манифест: `format`, `id`, `title`, `start`, `scenes` |
| `story.md` | да | все сцены |
| `items.yaml` | нет | предметы, если они есть в книге |
| `assets/` | нет | иллюстрации и звук |
| `stats.yaml`, `flags.yaml` | нет | характеристики и флаги (движок MVP их пока не читает) |

Готовые исходники «Стальной крысы» уже лежат в `games/steel-rat/` — можно копировать
структуру оттуда.

### game.yaml

```yaml
format: quest/1
id: koshchei-cave
title: Кощеева пещера
author: Гарри Гаррисон
language: ru
start: '1'                 # ключ стартовой сцены, строкой
story: story.md            # по умолчанию story.md
items: items.yaml          # только если есть предметы
start_items:               # с чем игрок начинает
  sword: 1
  sleep_grenades: 2
scenes:                    # метаданные сцен: заголовки, картинки, переходы
  '1':
    title: Глава 1. Вход в пещеру
    image: assets/cave-road.jpg
  '2':
    title: Глава 2. Зал
    next: '3'              # линейный переход без выбора
  '6':
    title: Глава 6. Провал
    next:                  # переход по броску кубика
      roll: 1d6
      outcomes:
        - min: 4
          goto: '4'
        - goto: '5'        # последний исход без min — обязательный
  '4':
    title: Глава 4. Богатая добыча
    ending: true           # концовка
```

Ключи сцен бывают числовыми (`'232'`) и текстовыми (`cave_hall`). Числовые в YAML
обязательно в кавычках, иначе YAML прочитает их как числа.

### story.md

```markdown
## 1

Тёмный вход в пещеру. Пахнет сыростью и старой золой.

- [Войти внутрь](2)
- [Осмотреть стены](3) {if: has_item rusty_key}
- [Поднять ключ](2) {take: rusty_key, use: sleep_grenades}
```

- сцена начинается с `## <ключ>`;
- текст — обычный Markdown, номера глав в тексте не пишутся (они в названии);
- выборы — список ссылок в конце сцены, `[подпись](ключ)`;
- модификаторы в фигурных скобках: `if`, `take`, `use`, `drop`;
- линейные переходы и броски задаются в `game.yaml` (`next`), а не в тексте.

### items.yaml

```yaml
items:
  sword:
    title: Меч
  rusty_key:
    title: Ржавый ключ
    description: Ключ от сундука.
  grenades:
    title: Гранаты
    countable: true       # учитывается количеством
    consumable: true      # тратится при use
```

## 2. Как добавить иллюстрации

1. Положи картинку в `games/<id>/assets/` — например `games/cave/assets/cave-road.jpg`.
2. В `game.yaml` у нужной сцены добавь строку:

```yaml
  '1':
    title: Глава 1. Вход в пещеру
    image: assets/cave-road.jpg
```

3. Пересобери игры: `npm run games:build` (или просто запусти `npm run dev` — сборка
   игр идёт автоматически перед стартом).

Путь всегда относительно папки игры. Поддерживаются jpg, png, webp; файлы копируются в
`public/games/<id>/assets/` при сборке.

**Как это выглядит:** кадр до 60% высоты экрана, картинка вписывается целиком
(`object-fit: contain`), по бокам остаются поля цвета экрана. Обрезки нет. Сканлайны и
виньетка ЭЛТ ложатся поверх изображения. Картинка прокручивается вместе с текстом:
сначала кадр, ниже текст сцены, поэтому на длинных главах читатель просто листает
дальше, а выборы всегда остаются внизу экрана. Если у сцены нет `image`, экран
показывает только текст.

Если картинка не появилась — проверь имя файла (регистр важен) и что в `game.yaml`
путь совпадает с реальным.

## 3. Сборка и проверка

```bash
npm run games:build   # только сборка игр
npm run dev           # сборка игр + дев-сервер на http://127.0.0.1:3100
npm run build         # сборка игр + продакшн-сборка
```

`games:build` — это и валидатор. Если в пакете ошибка, сборка падает и печатает список:

```text
ОШИБКИ СБОРКИ:
 - cave: сцена 2: переход в несуществующую сцену «7»
 - cave: сцена 4: take ссылается на необъявленный предмет «key»
 - cave: сцена 5: тупик без ending
```

Что проверяется:

- `format: quest/1`, наличие `start` и его существование;
- каждый заголовок `##` имеет метаданные в `game.yaml`, и наоборот;
- все переходы ведут в существующие сцены, тупиков без `ending` нет;
- предметы из `take`/`use`/`drop`/`if` и `start_items` объявлены;
- у броска есть последний исход без `min`;
- текст не идёт после списка выборов.

## 4. Как убрать игру

Удали папку `games/<id>/` и выполни `npm run games:build`. Старый JSON из
`public/games/` удалится автоматически — сборка чистит каталог перед работой.

## 5. Если книга ещё не в формате

Книгу в пакет превращает ИИ по инструкции QuestRules (приложение А.8); она лежит в корне
проекта, вне этого репозитория:
разбор секций, вынос навигации в переходы, проверка полноты, отчёт `review.md`.
Готовый пакет просто кладётся в `games/<id>/` — дальше всё делает `games:build`.
